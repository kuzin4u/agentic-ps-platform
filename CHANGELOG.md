# Журнал изменений

Изменения, заметные потребителям пакета: агенту (`agentic-buyer-ref`), ядру (`agentic-core`) и тем, кто подключает стенд
(`agentic-ps-platform/stand`) и фикстуры (`agentic-ps-platform/fixtures`). Версия пакета — `package.json`; тег `vX.Y.Z`
ставит владелец на коммит слияния в `main`. Версия ПАО — `info.version` в `docs/core/agent-protocol.yaml`, сверка копий —
по `PAO_SPEC_SHA256` (`src/shared/pao-errors.generated.ts`). Записи до v0.4.0 — в описаниях PR и тегах.

## v0.9.0 — 19.10.2026

PS-13 «Порог подтверждения и дробление в ADP», PR #40. ПАО — по-прежнему 1.4.0, `PAO_SPEC_SHA256` не меняется
(`48bd3397…9ad9da`); ядро — `#v0.8.0` без изменений. Решение РП44 с дополнениями п. 1–2. ПИ — описание
`split_detected` в `processing-interface.yaml` (новый `PI_SPEC_SHA256` `627d8775…`, схема прежняя).

### Меняет поведение для агента (схема ПАО прежняя)

- **Дробление по мандату в окне** (SPEC §6 п. 9, ПС12): авторизация не выше порога, при которой в окне
  `split_window_sec` (600 с) по корневому INTENT (у CART — родитель; несколько CART под одним INTENT — одно окно) вместе с
  ней не меньше `split_min_ops` (2) операций и их сумма выше порога, — `CONFIRMATION_REQUIRED` (`split_detected: true`),
  без резерва. Две покупки по 1 700 ₽ за 10 минут при пороге 3 000 ₽: вторая не одобряется.
- **До PS-19 долю не подтвердить:** `confirmation_ref` не проверяется, повтор получает тот же ответ — вторая покупка в
  окне не пройдёт до истечения окна.
- **Доля в залпе** одновременных авторизаций получает `CONFIRMATION_REQUIRED` (`split_detected: true`) или
  `LIMIT_EXCEEDED` — по моменту чтения остатка (доп. РП44 п. 1); обе реакции агента — не покупать.

### Порог подтверждения (РП44 п. 5)

- `T` = меньшее из рыночного `confirm_above_kop` (копейки RUB) и клиентского `Limits.confirm_above` (ПИ-8, PS-20);
  порт `ClientThresholds` до PS-20 не подключён — действует рыночный. Сбой порта или ответ не по форме —
  `STATE_UNAVAILABLE`. Операция не в RUB — `STATE_UNAVAILABLE` (порог в другой валюте не определён).
- `split_detected` в ответе ПИ-1: `true` — доля, `false` — порог одной операции, у прочих решений поля нет.

### Окно дробления (РП44 п. 4, доп. п. 2)

- Столбцы окна в `adp_operations` — `sql/104_adp_split_window.sql` (`window_key`, `amount`, `currency`,
  `window_at_ms`; индекс; триггеры: столбцы окна один раз у записи «в работе», вставка — без решения и окна).
- Вход — `OperationStore.enterWindow`: на PostgreSQL транзакция под `pg_advisory_xact_lock` ключа окна, ожидание
  блокировки не дольше `adp_timeout_ms` (`PgOperationStore` — обязательный `lockTimeoutMs`; **несовместимо** для тех,
  кто создавал `new PgOperationStore(pool)`); в памяти — без `await` между проверкой и записью.
- Журнал процесса: доля — запись `warn` с `split_detected: true` без реквизитов.

### Меняет смысл для агента (схема ПАО прежняя)

- **`verify.amount_left` у CART** — меньшее из остатков CART и родителя INTENT (РП43 п. 6). Авторизация по CART
  резервирует и бюджет CART, и бюджет родителя; несколько CART под одним INTENT в сумме не превышают его предела.

### Точка решения ADP (РП43)

- `POST /adp/v1/decide` (ПИ-1) — **на стенде** (`createStand`, 127.0.0.1) и в `buildServer({ adp })`; рабочий процесс
  (`npm start`) его не открывает до аутентификации процессинга (SEC-1, доп. РП43 п. 21).
- `BYPASS` — по двум полям (`aoi` нет или `null` и `instrument.kind = CARD_TOKEN`) до любой другой проверки и чтения
  хранилищ; агентским — порядок SPEC §6: признак (`aoi_rollout_phase` 3 — `AOI_MISSING` для агентского инструмента без
  признака), агентский токен до PS-14 — `CREDENTIAL_INVALID`, агент по реестру (`EXCLUDED` — `AGENT_UNKNOWN`), мандат
  агента и статус свёрткой, `merchant_scope` и валюта, порог `confirm_above_kop` до PS-13 — `CONFIRMATION_REQUIRED`
  без резерва, резерв в П3 по `op_ref`, сверка статуса после резерва.
- Коды П3 → ПИ — `STATE_TO_PI`; неподтверждённое состояние журнала, реестра или П3 — `DECLINE` / `STATE_UNAVAILABLE`,
  никогда не `BYPASS`. Некорректное агентское сообщение — 400 `{}`, сбой — 503 `{}`; процессинг ставит `ADP_UNAVAILABLE`.
- Идемпотентность по `op_ref`: запись операции «в работе» до резерва (в памяти; на PostgreSQL — `sql/103_adp_operations.sql`,
  условная вставка), повтор — прежнее решение, повтор с другим сообщением — `STATE_UNAVAILABLE`.
- Режим «только `BYPASS`» — `buildServer({ bypassOnly })`: `/health` с `mode: "bypass_only"` и кодами; в `npm start` — с
  SEC-1, до того `ready: false` — по-прежнему код выхода 1.

### Пока нет

- Проверки домена токена и криптограммы (PS-14), дробление и подтверждение (PS-13), лимит клиента (PS-20), события

### Ломает для потребителей стенда

- **Три новых обязательных параметра** (`params.stand.json` без них не загружается — тем, кто подаёт свой
  `PARAMS_PATH`, ключи нужно добавить):
  - `event_page_max` (100) — не больше стольких событий в ответе ленты (РП39 п. 7);
  - `event_delivery_timeout_ms` (5 000) — один предел на попытку push: разрешение имени, соединение, отправка, статус
    ответа (РП40 п. 4, доп. п. 10);
  - `event_subscription_allow_hosts` (`["agent-emulator.stand"]`) — разрешённые хосты адреса подписки, точное имя DNS.
    **Пустой список закрывает подписку всем** (fail-closed, РП40 п. 2).
- Миграции `sql/101_events.sql` (`pao_events`, только вставка) и `sql/102_event_deliveries.sql` (попытки push).

### ПАО (совместимо с 1.4.0)

- `GET /pao/v1/events?after=<event_id>` — лента событий агента: `mandate.signed`, `mandate.rejected`, `mandate.revoked`
  (отзыв клиентом и `relinquish`), `data` — только `{mandate_id}`, не больше `event_page_max` за ответ. Порядок задаёт
  только лента. Чужой, неизвестный или не по форме `after` — 400 `REQUEST_INVALID`.
- `PUT /pao/v1/subscription` с `Idempotency-Key` — `{url, events}`: `https://`, порт 443, имя (не IP) из
  `event_subscription_allow_hosts`, все адреса имени — глобальные (защита от SSRF, РП40 п. 2–3 и доп. п. 1, 17). Отказ
  самого адреса — 400 `REQUEST_INVALID` (сохраняется под ключом, исправленный адрес — с новым ключом); временный сбой или
  тайм-аут DNS — 503 `STATE_UNAVAILABLE`, повтор тем же ключом. Пустой `events` выключает push.
- Push: POST `Event` с заголовком `x-event-id` на адрес подписки; успех — только 2xx в пределах
  `event_delivery_timeout_ms`; без перенаправлений; адрес проверяется заново перед каждой отправкой, соединение — с
  проверенным IP. Повтор — по `nextAttemptDelayMs` ядра, до `event_retry_max` попыток всего, затем событие — только в
  ленте. Недоставленные события уходят по **текущей** подписке (доп. п. 11). Доставка «не менее одного раза» —
  обработка у агента идемпотентна по `event_id`.
- `SUSPENDED` / `EXCLUDED`: лента и подписка — 403 `AGENT_SUSPENDED`, push не выполняется и после снятия приостановки
  не догоняет — накопленное читается лентой; `agent.suspended` по push не приходит (РП40 п. 6–7).
- События не подписаны до ПАО 1.5.0: событие — сигнал, статус — через `GET /pao/v1/mandates/{id}` (РП39 п. 6).

### Стенд (`agentic-ps-platform/stand`)

- `stand.agentReceiver` — эмулятор агента-получателя по адресу `https://agent-emulator.stand/…`: `respond(...statuses)`

- `stand.deliverEvents()` — один проход доставки по часам стенда (таймера нет; повтор — `setClock`), число попыток.
- `stand.delivery(event_id)` — строка попытки (`state`, `attempts`, `last_reason`).
- `stand.dns` — подмена разрешения имени (`set`, `reset`): проверка адреса на стенде не отключается.

### Пока нет

- Подписи событий и ответов — ПАО 1.5.0 (SEC-1, Б4).
- Событий `operation.*`, `confirmation.*`, `agent.*` — PS-16, PS-17, PS-19.
- Остаточные риски доставки — STATUS «Открыто»: один медленный агент задерживает доставку всем (до второго агента),
