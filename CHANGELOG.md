# Журнал изменений

Изменения, заметные потребителям пакета: агенту (`agentic-buyer-ref`), ядру (`agentic-core`) и тем, кто подключает стенд
(`agentic-ps-platform/stand`) и фикстуры (`agentic-ps-platform/fixtures`). Версия пакета — `package.json`; тег `vX.Y.Z`
ставит владелец на коммит слияния в `main`. Версия ПАО — `info.version` в `docs/core/agent-protocol.yaml`, сверка копий —
по `PAO_SPEC_SHA256` (`src/shared/pao-errors.generated.ts`). Записи до v0.4.0 — в описаниях PR и тегах.

## v0.6.0 — 19.10.2026

PS-09 «Сервис состояния (П3)», PR #34. ПАО — по-прежнему 1.4.0, `PAO_SPEC_SHA256` не меняется: `EXHAUSTED`,
`STATE_UNKNOWN`, `mandate.exhausted`, `LIMIT_EXCEEDED` уже в перечнях; описание `verify` в YAML обновится с ПАО 1.5.0
(STATUS, расхождение № 28). Решение РП41 с дополнениями п. 14–24.

### Ломает для потребителей стенда

- Ничего: новых параметров и миграций нет (удержания — таблицы ядра `002_holds.sql`, уже применяются). Для агента меняется
  смысл полей — ниже.

### ПАО (совместимо с 1.4.0, меняется смысл)

- `verify.amount_left` — остаток бюджета мандата в П3: уменьшается **резервом** авторизации, восстанавливается
  реверсалом и освобождением, а не только списанием. Бюджет не прочитан при целом журнале — 200 `STATE_UNKNOWN` с
  `amount_left` = 0 (это «вне пределов», A7 п. 8.6). У CART до PS-10 — свой бюджет CART без учёта родителя INTENT.
- `EXHAUSTED` в `GET` и событие `mandate.exhausted` (`data` — `{mandate_id}`) — когда **закреплён** (списан по
  клирингу) весь предел; резерв на весь предел исчерпания не даёт. Событие может прийти дважды; статус — через `GET`.
  Отзыв и `relinquish` при `EXHAUSTED` — 200 без записи. Родитель `EXHAUSTED` — CART `EXHAUSTED`; запрос CART под ним —
  409 `LIMIT_EXCEEDED` (`after_human`).
- В `evidence.records` — новый вид записи `MANDATE_EXHAUSTED` (`payload` `{committed, currency}`): `ACTIVE` →
  `EXHAUSTED`, дубль пропускается, отзыв после неё — `REVOKED`, срок на `EXHAUSTED` не действует. Агент, сворачивающий
  выписку сам, должен знать этот вид (на неизвестный — останавливаться).
- Операция по мандату `REJECTED` (с ADP, PS-10) — `MANDATE_REVOKED`, как по отозванному.

### Стенд (`agentic-ps-platform/stand`)

- П3 подключён к стенду (удержания ядра в памяти, часы стенда): счёт мандата открывается при подписи эмулятором эмитента.
  Резервов на стенде до PS-10 (ADP) нет — `amount_left` после подписи равен `amount_limit`.

### Пока нет

- Резерв в пути авторизации (ADP) — PS-10; события процессинга (клиринг, реверсал) — PS-16.
- Лимит клиента («меньшее из пределов», A3 п. 7.2) — PS-20; уведомление клиента об исчерпании — PS-07/PS-20.

## v0.5.0 — 18.10.2026

PS-08 «Доставка событий агенту (П9)», PR #31 (лента) и PR #32 (подписка и push). ПАО — по-прежнему 1.4.0,
`PAO_SPEC_SHA256` не меняется (РП39 п. 8): новые ответы методов (400, 403, 503) объявляются в YAML с ПАО 1.5.0
(STATUS, расхождения № 20, № 24). Решения РП39, РП40 с дополнениями п. 1–18.

### Ломает для потребителей стенда

- **Три новых обязательных параметра** (`params.stand.json` без них не загружается — тем, кто подаёт свой
  `PARAMS_PATH`, ключи нужно добавить):
  - `event_page_max` (100) — не больше стольких событий в ответе ленты (РП39 п. 7);
  - `event_delivery_timeout_ms` (5 000) — один предел на попытку push: разрешение имени, соединение, отправка, статус
    ответа (РП40 п. 4, доп. п. 10);
  - `event_subscription_allow_hosts` (`["agent-emulator.stand"]`) — разрешённые хосты адреса подписки, точное имя DNS.
    **Пустой список закрывает подписку всем** (fail-closed, РП40 п. 2).
- Миграции `sql/101_events.sql` (`pao_events`, только вставка) и `sql/102_event_deliveries.sql` (попытки push).

### ПАО (совместимо с 1.4.0)

- `GET /pao/v1/events?after=<event_id>` — лента событий агента: `mandate.signed`, `mandate.rejected`, `mandate.revoked`
  (отзыв клиентом и `relinquish`), `data` — только `{mandate_id}`, не больше `event_page_max` за ответ. Порядок задаёт
  только лента. Чужой, неизвестный или не по форме `after` — 400 `REQUEST_INVALID`.
- `PUT /pao/v1/subscription` с `Idempotency-Key` — `{url, events}`: `https://`, порт 443, имя (не IP) из
  `event_subscription_allow_hosts`, все адреса имени — глобальные (защита от SSRF, РП40 п. 2–3 и доп. п. 1, 17). Отказ
  самого адреса — 400 `REQUEST_INVALID` (сохраняется под ключом, исправленный адрес — с новым ключом); временный сбой или
  тайм-аут DNS — 503 `STATE_UNAVAILABLE`, повтор тем же ключом. Пустой `events` выключает push.
- Push: POST `Event` с заголовком `x-event-id` на адрес подписки; успех — только 2xx в пределах
  `event_delivery_timeout_ms`; без перенаправлений; адрес проверяется заново перед каждой отправкой, соединение — с
  проверенным IP. Повтор — по `nextAttemptDelayMs` ядра, до `event_retry_max` попыток всего, затем событие — только в
  ленте. Недоставленные события уходят по **текущей** подписке (доп. п. 11). Доставка «не менее одного раза» —
  обработка у агента идемпотентна по `event_id`.
- `SUSPENDED` / `EXCLUDED`: лента и подписка — 403 `AGENT_SUSPENDED`, push не выполняется и после снятия приостановки
  не догоняет — накопленное читается лентой; `agent.suspended` по push не приходит (РП40 п. 6–7).
- События не подписаны до ПАО 1.5.0: событие — сигнал, статус — через `GET /pao/v1/mandates/{id}` (РП39 п. 6).

### Стенд (`agentic-ps-platform/stand`)

- `stand.agentReceiver` — эмулятор агента-получателя по адресу `https://agent-emulator.stand/…`: `respond(...statuses)`
  — ответы по очереди, `received` — все попытки, `handled` — обработанные события (идемпотентно по `event_id`).
- `stand.deliverEvents()` — один проход доставки по часам стенда (таймера нет; повтор — `setClock`), число попыток.
- `stand.delivery(event_id)` — строка попытки (`state`, `attempts`, `last_reason`).
- `stand.dns` — подмена разрешения имени (`set`, `reset`): проверка адреса на стенде не отключается.

### Пока нет

- Подписи событий и ответов — ПАО 1.5.0 (SEC-1, Б4).
- Событий `operation.*`, `confirmation.*`, `agent.*` — PS-16, PS-17, PS-19.
- Остаточные риски доставки — STATUS «Открыто»: один медленный агент задерживает доставку всем (до второго агента),
  зависший DNS занимает пул потоков (до боевого запуска), только первый проверенный адрес.

## v0.4.0 — 18.10.2026

PS-06 «Журнал согласий (П2)», PR #30. ПАО 1.4.0, `PAO_SPEC_SHA256` =
`48bd339746e83c0468fb8354d6b2d8f0c82020904af549063d3e44b1a51ad9da`. Решения РП33–РП38.

### Ломает для потребителей стенда

- **`PARTICIPANT_KEYS_PATH`: у участника обязателен `revocation_order`** (РП37). Запись участника без него или с разными
  значениями в записях ключей одного участника — ошибка при старте. Если порядок отзыва у участника не задан, запрос
  мандата получает 503 (РП37 п. 4).
- **`signature_ref` и `revocation_ref` в ПИ-8 — по маске без ПДн** (РП38 доп. п. 2): латиница, цифры, `_`, `-`, до 64
  знаков, без семи цифр подряд; иначе 400 `REQUEST_INVALID`. Ссылки уходят агенту в выписке.

### ПАО 1.4.0 (совместимо с 1.3.0, AGENT-PROTOCOL §7)

- `POST /pao/v1/mandates` (INTENT, CART под INTENT): id мандата вычисляется от агента и `Idempotency-Key`, повтор тем же
  ключом — тот же мандат в любой срок (РП33 доп.); ответы 401/403/404/409/503 объявлены (РП33, РП35).
- `GET /pao/v1/mandates/{id}`: чужой и неизвестный — одинаковый 404 `MANDATE_NOT_FOUND` (РП34).
- `Mandate.revocation_order` и `Mandate.agent_code` — обязательные поля ответа; порядок отзыва — от Платформы из записи
  участника, входит в `Mandate.hash` (РП37).
- `POST /pao/v1/mandates/{id}/relinquish` — отказ агента от полномочий (РП38 п. 3).
- `GET /pao/v1/mandates/{id}/verify` — ровно `{outcome, amount_left, valid_to, as_of}`, без предмета (РП38 п. 6).
- `GET /pao/v1/mandates/{id}/evidence` — выписка с `records`: цепочка и подписи банка проверяются без Платформы (РП38 п. 7).
- Статус CART при отзыве или истечении родителя — РП35; правило свёртки записей — в AGENT-PROTOCOL §3 (РП38 п. 5).
- Ответы и события Платформы в 1.4.0 по-прежнему не подписаны: подпись — ПАО 1.5.0 (РП26, РП37).

### ПИ-8 (шлюз участников)

- `POST /participants/v1/mandates/{id}/sign` — решение клиента (подпись или отказ) с подписью Ed25519 банка, метка
  `pao:participant-mandate-signature:v1` (РП36).
- `POST /participants/v1/mandates/{id}/revoke` — отзыв клиентом через банк, метка
  `pao:participant-mandate-revocation:v1` (РП38 п. 1).

### Стенд (`agentic-ps-platform/stand`)

- `issuer.sign(mandateId, opts?)` — эмулятор эмитента подписывает мандат и шлёт тот же запрос ПИ-8 `sign`.
- `issuer.revoke(mandateId)` — отзыв клиентом через эмулятор эмитента (ПИ-8 `revoke`).
- `issuer.trustedKey` — открытый ключ эмулятора: проверка подписей банка в выписке без Платформы.

### Пока нет

- Событий `mandate.signed` и `mandate.revoked` агенту — PS-08.
- Остатка бюджета в `verify`: до PS-09 — предел мандата.
