# План «Россия»: агент покупателя и платформа-песочница для НСПК

Редакция 1 · 14.10.2026 · Заменяет совместный план ред. 6–8 (источник правды по решению владельца 14.10.2026). Один из двух планов по рынкам (решение владельца 14.10.2026). Второй — **план «Запад»** (`docs/reference/plan-west.md`). Общий календарь — в обоих планах, раздел 1. Этот план содержит **общее ядро (инвариант)**: план «Запад» опирается на его задачи как на зависимости.

**Цель:** заявить о себе и забронировать место — **российский MVP к 31.10** (С3 и экраны агента и мандатов, сроки ред. 7), готовность к пилоту (С6) к концу ноября, **пилот с НСПК — апрель 2027**.

**Состав:** 58 исходных задач продукта + экраны (UI-К1, UI-К2) + каталог для России (CO-К1…К3, PS-К1, AG-К1) + адаптер НСПК (AG-К13) и ГОСТ (CO-К7) + документы для НСПК и банков (DOC-К1, DOC-К2) + OWN-5. Всего 70.

**Правила совместимости (для обоих планов, проверяются на ревью каждого кирпича):** 1) агент работает с платформой только через порт; 2) сумма — пара «число в минимальных единицах + валюта», даже если пока только рубли; 3) экраны — с переключением языка и настройкой бренда с первого коммита. Что совпадает между рынками, что настраивается, дорабатывается или разрабатывается заново — документ решений, раздел 9.

## 5. Правила координации

- Протокол ПАО — единственный стык. Владелец — платформа; изменение через `/decision` в платформе, переход агента на версию — своим `/decision` после контрактных тестов.
- Точка сверки — прогон, а не созвон. Следующий этап агента против песочницы не начинается, пока точка не зелёная в CI обоих репозиториев.
- Агент не ждёт. Не хватает функции платформы — мок и запись в разделе `STATUS.md` «Ждём от платформы».
- Платформа разблокирует агента. `/start` платформы читает «Ждём от платформы» в репозитории агента.
- Опережение платформы — не больше этапа. Если больше — следующая сессия агенту.
- Кирпичи (Д1, Д2, 14.10.2026). Справка перед сессией раскладывает задачу на подзадачи и кирпичи; кирпич — логически цельная правка, один коммит после «да» владельца и ревью. В описании PR — чеклист «Кирпичи» со ссылками на коммиты; шаги из ревью («Шаги к выполнению») и найденные по ходу — с источником; незакрытое — в STATUS «Следующая сессия».
- Подставные поломки. Тест считается рабочим, когда временная поломка кода его краснит; для CI — временный коммит и revert, оба прогона — в чеклисте.
- Слияние и теги — только владелец. Тег — на коммит слияния; команду с хэшем даёт /finish.
