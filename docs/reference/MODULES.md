# Модульная структура: агентная коммерция, расчёты, магазины

Редакция 2 · 08.10.2026 — после сверки с GitHub (`kuzin4u`). Периметр — проекты massamadre (`Sourdough-Bakery`), lucklyrics-platform, marketplace-api, buyer-agent (`buyer_agent`), agentic-buyer-ref, agentic-ps-platform, «агент покупателя НСВР», myasnitski-agent (`meat_agent`). Для устранения дублирования добавлены два модуля: `agentic-core` и `nsvr-settlement`.

**Что изменилось против редакции 1.** `buyer_agent` оказался не диалоговой оболочкой агента покупателя, а агентом-закупщиком на Python: аналитик собственных покупок по чекам ФНС (ядро А), с экспортом профиля по замороженной схеме 1.0. Его спецификация (§9) прямо называет этот экспорт единственным мостом к агенту покупателя Системы. Поэтому buyer_agent — источник знания о человеке (слой 4, рядом с ядром, а не над ним), а связь с ядром — через JSON профиля и, для расширения Б, через HTTP.

Документ лежит в `ecosystem-docs` и копией — в `docs/reference/` каждого репозитория. При расхождении норма — версия в `ecosystem-docs`.

## 1. Главное правило

**Каждая функция живёт ровно в одном модуле.** Остальные модули пользуются ею через контракт (API или пакет) и не держат своей копии. Если функция нужна двоим — она уходит вниз, в общий слой.

## 4. Правила зависимостей

1. Зависимости идут только вниз по слоям: экземпляр → продукт → движок → платформа → общий пакет. Обратных нет.
2. Модули одного слоя связаны только через контракты (API), не через код и не через общую базу.
3. Никто не зависит от экземпляров (massamadre, myasnitski-agent).
4. ПС-платформа не зависит ни от marketplace-api, ни от nsvr-settlement: она нейтральна. Они подключаются к ней на публичных условиях.
5. nsvr-settlement не зависит от marketplace-api; marketplace-api вызывает nsvr-settlement, когда заказ рассчитывается через Систему.
6. agentic-core не зависит ни от кого.

## 6. Сквозные сценарии (как модули работают вместе)

**Покупка агентом в каталоге Системы.** Человек → оболочка (расширение Б buyer_agent или эталонная оболочка) → ядро получает профиль 1.0 от buyer_agent → мандат через ПАО (ПС-платформа, подпись в банке) → поиск через Agent Service API (marketplace-api) → заказ в marketplace-api (сумму и сплит считает он) → реквизит ПАО → пакет продавцу → авторизация (процессинг → ADP ПС-платформы) → marketplace-api передаёт заказ в nsvr-settlement как сделку → банк-эскроу `FUNDED` → подтверждение получения человеком → nsvr-settlement `commit` по сплиту marketplace-api → итог ПС-платформе через `/cx/v1`.

**Покупка на витрине massamadre без агента.** massamadre (экземпляр lucklyrics-platform) → прямая оплата продавцу или, по настройке канала, расчёт через Систему → дальше как выше, без ПС-платформы.

**Консультант на витрине Мясницкого ряда.** myasnitski-agent (знания и настройки) на движке агентов lucklyrics-platform. Денег не касается; если ему пишет агент покупателя — отвечает как агент продавца (класс SELLER), без доступа к мандату.
