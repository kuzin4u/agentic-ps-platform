# Готовность к пилоту: отчёт SEC-2

Редакция 1 · 02.11.2026 · Платформа v0.38.0 (SEC-2 ч. 1 — PR #93, ч. 2 — PR #94). Строка плана «Россия» ред. 4 — SEC-2 «Проверка безопасности перед пилотом»: ворота перед реальными деньгами. Источники — SECURITY §7 (сверка с кодом), §8 (внешние зависимости), STATUS «Открыто».

## 1. Итог

- **Песочница MVP (без пути покупки) — код готов к установке и приёмке** при условиях раздела 3; установка и живая приёмка — после аккаунта Yandex Cloud (STATUS «Следующая сессия»). Состав: допуск агента с mTLS и сертификатом по CSR, мандаты с подписью тестового банка-участника по ПИ-8, лимиты частоты у всех открытых адресов, журналы без реквизитов и ключей на стенде.
- **Пилот с банком на реальных деньгах — не готов.** Держат: подпись ответов и событий (ПАО 1.5.0), путь покупки в `main.ts` (ADP, П5, П6), внешние зависимости оператора и банка (раздел 5) и задачи раздела 4.

## 3. Принятые риски и пределы проверок

1. **Dependabot alert 20** — только разработка; пересмотр 10.11 (обновление цепочки или `overrides` через `/decision`).
2. **CodeQL #87** — см. раздел 2; закрыта только после анализа `main`.
3. **С3б** — лимит по адресу не защищает от перебора с многих адресов и коротких или словарных кодов (РП73 п. 5).
4. **Сканер журналов** ловит известные шаблоны и значения; новое поле с сырым значением другого вида — нет (белый список имён полей — PS-33). Страж имён не ловит значение под другим именем (`{ value: c }`).
5. **Журнал компонентов на стенде не подключён** (П3, П5, П8, ADP): живой сканер их записи не видит. **Условие готовности пути покупки:** в той же задаче, где ADP и П5 входят в `main.ts` (РП70), — подключить им журнал и прогнать сканер журналов по `main.ts`; до этого путь покупки готовым не считать.
6. **Сквозная оговорка §7:** «закрыто» по ADP, П5, П6 — на стенде; в песочнице их нет (А7 — остаточный риск).
7. **152-ФЗ:** `mandate_id` и `remoteAddress` в журнале процесса — правила доступа и срок хранения — PS-33.
