# Протокол агентских операций (ПАО) v1.1

Редакция 2 · 08.10.2026 (v1.1.0: условное исполнение, РП13). Машиночитаемый контракт — `agent-protocol.yaml`. Владелец протокола — репозиторий Платформы. BuyerAgent хранит копию с фиксированной версией и проверяет совместимость контрактными тестами (РП7).

## 1. Назначение и границы

ПАО — интерфейс, через который агент покупателя (BuyerAgent и любые другие допущенные агенты) взаимодействует с Платформой платёжной системы.

Через ПАО агент:
- узнаёт свой статус и управляет ключами;
- запрашивает мандаты, а принципал подписывает их в банке;
- проверяет мандат и остаток;
- получает **агентский платёжный реквизит** на конкретный заказ;
- узнаёт о подтверждениях, авторизациях, расчётах, отзывах и приостановлениях;
- подаёт спор по поручению человека и получает выписку из журнала.

Чего через ПАО **нет**:
- авторизации платежа — её инициирует продавец через эквайрера (РП2);
- номера карты, счёта и любых платёжных реквизитов принципала;
- персональных данных принципала — только ссылка `principal_ref`;
- изменения ограничений — это делает человек в банке (A3 п. 2.2).

## 2. Транспорт и безопасность

- HTTPS, TLS 1.2+; **mTLS**: клиентский сертификат выдаётся при допуске и связан с `agent_code`. В контуре оператора — ГОСТ TLS.
- **Подпись каждого обращения** (HTTP Message Signatures): подписываются `@method`, `@path`, `@query`, `content-digest`, `x-agent-code`, `x-timestamp`, `x-nonce`. Алгоритм — по ключу (`ed25519` в песочнице, ГОСТ Р 34.10-2012 в контуре оператора). Окно времени — `signature_skew_sec`; `x-nonce` не повторяется в пределах окна.
- **Код агента, класс и уровень** Платформа берёт из реестра по сертификату и ключу. Значения в теле запроса игнорируются.
- **Идемпотентность:** изменяющие методы требуют `Idempotency-Key`. Повтор с тем же ключом и тем же телом возвращает прежний результат; с тем же ключом и другим телом → `IDEMPOTENCY_CONFLICT`.
- **Ограничение частоты** зависит от уровня допуска; превышение → `RATE_LIMITED` с `Retry-After`.
- **Ответы и события Платформы подписаны** её ключом (`Platform-Signature`). Агент обязан проверять подпись событий. Ключи Платформы — в `/.well-known/pao-configuration`.

Пример заголовков:

```
POST /pao/v1/credentials
X-Agent-Code: nspk:agent:buyref-01:v3
X-Timestamp: 2026-10-08T08:41:12Z
X-Nonce: 3f9a1c0e
Idempotency-Key: 7c1f-...-a904
Content-Digest: sha-256=:9f2b...:
Signature-Input: sig1=("@method" "@path" "@query" "content-digest" "x-agent-code" "x-timestamp" "x-nonce");keyid="k-2026-10";alg="ed25519"
Signature: sig1=:MEQCIF...:
```

## 4. Агентский платёжный реквизит и пакет для продавца

`POST /pao/v1/credentials`:

```json
{
  "mandate_id": "MND-8f31c0",
  "order_ref": "ORD-77a1",
  "merchant_id": "MER-1042",
  "amount_max": 189000,
  "currency": "RUB",
  "kind": "CARD"
}
```

Условия выдачи: мандат CART действует; `merchant_id` в его области; `amount_max` ≤ сумме мандата корзины; агент ACTIVE. Ответ:

```json
{
  "credential_ref": "CRD-91b0",
  "kind": "CARD",
  "payload": { "token_ref": "tok_ag_7f2c", "cryptogram": "base64...", "valid_to": "2026-10-08T08:56:12Z" },
  "aoi": { "indicator": true, "agent_code": "nspk:agent:buyref-01:v3", "mandate_id": "MND-8f31c0" }
}
```

Агент передаёт продавцу **пакет агентской оплаты**: `payload`, `aoi`, ссылку на мандат корзины и свою подпись пакета. Продавец или эквайрер переносят `aoi` в авторизацию (ПИ-2). Криптограмма одноразовая и годится только для этого продавца и суммы не выше `amount_max`.

Для `kind = SBP` в `payload` — идентификатор агентского списания по привязке счёта; списание инициирует продавец через банк-участник.

## 5. События

Доставка — POST на адрес подписки, тело подписано Платформой; повтор с экспоненциальной задержкой до `event_retry_max`. Обработка у агента обязана быть идемпотентной по `event_id`.

| Событие | Когда | Что обязан сделать агент (SPEC BuyerAgent) |
|---|---|---|
| `mandate.signed` | Принципал подписал | Продолжить стадию |
| `mandate.rejected` | Принципал отказал | Сообщить человеку, остановиться |
| `mandate.revoked` | Отзыв | Остановить начатое, отчитаться о незавершённом (Т13) |
| `mandate.exhausted` | Бюджет исчерпан | Уведомить человека |
| `confirmation.required` | ADP потребовала подтверждения | Передать человеку ссылку, не имитировать (Т7) |
| `confirmation.approved` / `.rejected` / `.expired` | Итог подтверждения | Повторить через продавца с `confirmation_ref` / остановиться |
| `operation.authorized` | Авторизация одобрена | Показать человеку |
| `operation.declined` | Отказ, `reason` из ПИ-1 | Поведение по таблице отказов (раздел 6) |
| `operation.settled` | Клиринг, запись об исполнении | Итог и документы человеку (Т11) |
| `operation.refunded` | Возврат | Показать человеку |
| `agent.key_revoked` | Отзыв ключа | Перейти на новый ключ или остановиться |
| `agent.suspended` / `agent.reinstated` | Статус допуска | Остановиться / продолжить |
| `dispute.updated` | Решение по спору | Сообщить человеку |

**Правило источника истины.** О результате операции агент узнаёт из события Платформы, а не со слов продавца. Если сообщение продавца расходится с событием Платформы, агент верит Платформе и записывает расхождение.

## 6. Ошибки

Тело ошибки: `{ "code", "message", "norm", "retry": "never|after_fix|same_key|new_key|after_human" }`.

| Код | HTTP | Причина | `retry` |
|---|---|---|---|
| AGENT_UNKNOWN | 401 | Нет в реестре | never |
| AGENT_SUSPENDED | 403 | Приостановлен | never |
| AGENT_KEY_REVOKED | 401 | Ключ отозван или истёк | new_key |
| SIGNATURE_INVALID | 401 | Подпись, окно времени, повтор nonce | after_fix |
| MANDATE_NOT_FOUND | 404 | — | after_human |
| MANDATE_EXPIRED | 409 | — | after_human |
| MANDATE_REVOKED | 409 | — | never |
| MANDATE_SCOPE | 409 | Продавец, категория или сумма вне мандата | after_human |
| PRINCIPAL_SIGNATURE_PENDING | 409 | Мандат ещё не подписан | after_human |
| LIMIT_EXCEEDED | 409 | Ограничение инструмента | after_human |
| STATE_UNAVAILABLE | 503 | Состояние не подтверждено | after_fix |
| CONFIRMATION_REQUIRED | 428 | Нужно подтверждение | after_human |
| CREDENTIAL_INVALID | 409 | Реквизит использован, истёк, не для этого продавца | after_fix |
| CREDENTIALS_FORBIDDEN | 422 | В запросе есть платёжные реквизиты | never |
| IDEMPOTENCY_REQUIRED | 400 | Нет ключа | same_key |
| IDEMPOTENCY_CONFLICT | 409 | Тот же ключ, другое тело | after_fix |
| RATE_LIMITED | 429 | Частота | after_fix |
| UPSTREAM_UNAVAILABLE | 503 | Компонент Платформы недоступен | after_fix |

## 7. Версии и совместимость

- Версия в пути (`/pao/v1`). Совместимые изменения — новые необязательные поля и новые типы событий; агент обязан игнорировать неизвестные поля и события.
- Несовместимые изменения — только новой версией с периодом параллельной работы не меньше `protocol_overlap_days`.
- `GET /.well-known/pao-configuration` сообщает поддерживаемые версии и дату вывода старых.

## 8. Соответствие отраслевым протоколам

| ПАО | AP2 | EMVCo (черновик) | A2A |
|---|---|---|---|
| Мандат INTENT | Intent Mandate | Open mandate / Intent | — |
| Мандат CART | Cart Mandate | Checkout / closed mandate | — |
| Реквизит + `aoi` | Payment Mandate | Agentic Transaction Indicator | — |
| Журнал согласий, `verify` | — | Intent Services | — |
| Реестр, ключи | — | Know Your Agent | Agent Card (подписанная) |

Агент публикует Agent Card (A2A) с расширением `x-system`: `agent_code`, класс, принципал (тип), источник знания, ссылка на `/.well-known/pao-configuration` Платформы. Платформа при допуске сверяет карточку с заявлением. Отступления фиксируются в журнале расхождений (A9 п. 5).

## 8а. Условное исполнение (v1.1.0)

Мандат с `settlement_mode = CONDITIONAL` и `conditional = {provider, deal_ref}` направляет оплату на счёт эскроу поставщика условного исполнения. `deal_ref` переносится в признак и операции; итог сделки приходит событиями `deal.funded`, `deal.released`, `deal.returned`. Метода «раскрыть эскроу» в ПАО нет. Подробно — `CONDITIONAL-EXECUTION.md`.

## 9. Переход от испытательного контура пула к ПАО

| Испытательный контур пула (`/v1`) | ПАО |
|---|---|
| `GET /v1/agents/{code}` | `GET /pao/v1/agent` |
| `POST /v1/mandates` | `POST /pao/v1/mandates` (+ подпись принципала в банке, событие `mandate.signed`) |
| `GET /v1/mandates/{id}/verify` | `GET /pao/v1/mandates/{id}/verify` |
| `PUT /v1/instruments/{token}/limits` | только человек через эмитента (ПИ-8); агенту недоступно |
| `POST /v1/pay/authorize` | `POST /pao/v1/credentials` → пакет продавцу → авторизация через эквайрера; результат — событием |
| `POST /v1/pay/confirm` | подтверждение человеком на УПК или в приложении банка; событие `confirmation.approved` |
| `POST /v1/disputes` | `POST /pao/v1/disputes` (+ `principal_ack`) |
| `GET /v1/runs/{id}/report` | в песочнице Платформы: `GET /sandbox/v1/runs/{id}/report` |
