## Передача агенту (AG-03 Подписант)

**PS-08 часть 1 (РП39, PR #31 — слит в main 18.10, тега нет; для AG-06 — агент может начинать на pull-ленте, решение владельца 18.10):** `GET /pao/v1/events?after=<event_id>` — события только вашего агента по порядку, не больше `event_page_max` (100); курсор — `event_id` последнего обработанного; без `after` — с начала; чужой, неизвестный, пустой, не по форме `after` — 400 `REQUEST_INVALID` (в YAML — с ПАО 1.5.0). События `mandate.signed`, `mandate.rejected`, `mandate.revoked` (отзыв клиентом и ваш `relinquish`); `data` — только `{mandate_id}`; у CART без своей записи событий нет. **До ПАО 1.5.0 событие не подписано — сигнал: перечитать `GET /pao/v1/mandates/{id}` и действовать по статусу**; дубли и события без смены статуса — норма. Приостановленному и исключённому агенту лента — 403 `AGENT_SUSPENDED` (РП40 п. 6–7, как `GET` мандата): события сохраняются, после снятия приостановки — лента с курсора.

**PS-08 часть 2 (РП40, PR #32 — черновик; для AG-06, push — после слияния):** `PUT /pao/v1/subscription` с `Idempotency-Key`, тело `{url, events}`: `url` — только `https://`, порт 443, имя хоста (не IP) из списка оператора (стенд — `agent-emulator.stand`), все адреса имени — глобальные; иначе 400 `REQUEST_INVALID` (сохраняется под ключом — исправленный адрес с новым ключом); временный сбой DNS — 503 `STATE_UNAVAILABLE` (повтор тем же ключом по `Retry-After`); `events` — типы `Event.type` без повторов, пустой — push выключен; подписка действует на события после неё. Push (сессия 18): POST с `Event` и `x-event-id`, успех — только 2xx в пределах `event_delivery_timeout_ms` (5 с), без перенаправлений, до `event_retry_max` (8) попыток с растущей задержкой, затем — только лента; при `SUSPENDED`/`EXCLUDED` push не идёт и не догоняет. Push не заменяет ленту: при старте, после сбоя и после приостановки — лента с курсора. Стенд: `stand.dns.set(host, addresses)` / `reset()` — подмена DNS для тестов агента.

Строки для первой сессии агента (AG-01…AG-03): переносятся в `../agentic-buyer-ref` там, а не из платформы; источник — РП23, РП24.
- Код агента — только `nspk:agent:<id>:v<N>`: оператор указывает его в заявлении, реестр выдаёт решением о допуске.
- `kid` — отпечаток JWK открытого ключа по RFC 7638 (`{"crv","kty","x"}`, SHA-256, base64url без дополнения); агент вычисляет сам, не выдумывает. Эталон — RFC 8037 прил. A.3.
- `public_key` — DER SubjectPublicKeyInfo в канонической записи base64 (RFC 4648 §3.5; как `newEd25519Signer` из agentic-core); лишние биты перед «=», без дополнения, пробелы, base64url — `KEY_INVALID` (РП23 доп. 6; расхождение № 8 агента). Пару генерирует оператор агента.
- Слабые ключи Ed25519 (точки малого порядка, неканоническая запись) — `KEY_INVALID` при допуске и регистрации.
- **Тег `v0.1.1`** (после слияния задачи PS-key-b64, ставит владелец) — `v0.1.0` + каноническая запись `public_key`; в 3d подключать его: `git+https://github.com/kuzin4u/agentic-ps-platform.git#v0.1.1`. Интерфейс стенда не менялся.
- `Retry-After` у ответов 503 — не больше 30 с (= `maxRetryAfterSec` клиента core, РП24).
- `GET /pao/v1/agent` подписывается с `content-digest` пустого тела (РП16); отвечает и приостановленному агенту.
- **SEC-1 (РП26, РП27; код — PS-05, PS-08, ПАО 1.5.0):** ключ сертификата mTLS генерирует оператор агента и передаёт CSR; сертификат — в решении о допуске, код агента в SAN URI `urn:nspk:agent:<id>:v<N>`; код из сертификата ≠ `x-agent-code` — `AGENT_UNKNOWN`, истёкший или отозванный сертификат — `AGENT_KEY_REVOKED`.
