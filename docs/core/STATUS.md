## Передача агенту (AG-03 Подписант)

Строки для первой сессии агента (AG-01…AG-03): переносятся в `../agentic-buyer-ref` там, а не из платформы; источник — РП23, РП24.
- Код агента — только `nspk:agent:<id>:v<N>`: оператор указывает его в заявлении, реестр выдаёт решением о допуске.
- `kid` — отпечаток JWK открытого ключа по RFC 7638 (`{"crv","kty","x"}`, SHA-256, base64url без дополнения); агент вычисляет сам, не выдумывает. Эталон — RFC 8037 прил. A.3.
- `public_key` — DER SubjectPublicKeyInfo в канонической записи base64 (RFC 4648 §3.5; как `newEd25519Signer` из agentic-core); лишние биты перед «=», без дополнения, пробелы, base64url — `KEY_INVALID` (РП23 доп. 6; расхождение № 8 агента). Пару генерирует оператор агента.
- Слабые ключи Ed25519 (точки малого порядка, неканоническая запись) — `KEY_INVALID` при допуске и регистрации.
- **Тег `v0.1.1`** (после слияния задачи PS-key-b64, ставит владелец) — `v0.1.0` + каноническая запись `public_key`; в 3d подключать его: `git+https://github.com/kuzin4u/agentic-ps-platform.git#v0.1.1`. Интерфейс стенда не менялся.
- `Retry-After` у ответов 503 — не больше 30 с (= `maxRetryAfterSec` клиента core, РП24).
- `GET /pao/v1/agent` подписывается с `content-digest` пустого тела (РП16); отвечает и приостановленному агенту.
- **SEC-1 (РП26, РП27; код — PS-05, PS-08, ПАО 1.4.0):** ключ сертификата mTLS генерирует оператор агента и передаёт CSR; сертификат — в решении о допуске, код агента в SAN URI `urn:nspk:agent:<id>:v<N>`; код из сертификата ≠ `x-agent-code` — `AGENT_UNKNOWN`, истёкший или отозванный сертификат — `AGENT_KEY_REVOKED`. Ответы и события Платформы подписаны по RFC 9421 (метка `platform`, `created`, ответ привязан к запросу через `;req`); ключи — в `platform_keys` `/.well-known/pao-configuration`, проверять `use`; неизвестный `kid` — одно перечитывание, затем отказ. Проверка — `verifyResponse` agentic-core (задача к CO). В копии ПАО 1.2 агента `Platform-Signature` остаётся до 1.3.0. До переезда хранилища перезапуск песочницы = повторный допуск агента (SECURITY.md §6).
- **РП22 (код — PS-12, PS-30, CO-4):** продавцы проверяют подпись агента по каталогу ключей JWKS (`kid` = `Key.kid` ПАО, частные члены `agent_code`, `nbf`, `exp`); ключ агента должен быть зарегистрирован, иначе продавец его не найдёт. Пакет агентской оплаты — `PaymentPackage`: `credential_ref`, `kind`, `payload`, `aoi`, `cart_mandate_id`, `order_ref`, подпись агента RFC 9421 тем же ключом; суммы в пакете нет. Ключи Платформы (`platform_keys`) перечитывать по неизвестному `kid` не чаще одного раза в `platform_keys_refetch_min_sec` (РП26 п. 6, дополнение РП22 п. 3).
- **PS-12 (после слияния PR #27 и тега; для AG-04, AG-09):**
